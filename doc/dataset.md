# Датасет `energy_obj`

Локальный датасет детекции объектов электроэнергетики, подготовленный из YOLO-экспортов Label Studio. Используется для обучения через MMDetection (`YOLOTxtDataset`) и Ultralytics YOLO.

## Назначение

Детекция на ортоснимках объектов ЛЭП и подстанций пяти классов. Изображения — большие ортотрансформированные тайлы (~10000×10000 px) с пространственной привязкой; целевые объекты (опоры, трансформаторы, подстанции) — маленькие, поэтому аннотации — это нормализованные боксы в пиксельной системе координат всего тайла.

## История сборки

1. **Базовая сборка** из экспортов Label Studio `energy2` (собран на другой машине, путь сохранён в `metadata.json → source_root`): 211 размеченное + 1 неразмеченное изображение (Alikino-2-8). Регионы: Alikino, Mendeleevo, NPZ_OSKINO, LISTVA, GAZ, KARPOVKA.
2. **Мерж `raw_part2`** — 10 проектов из `data/raw_part2/extracted` (project-7…project-16, экспорты от 2026-10-22): +1369 изображений, датасет вырос до 1581. Разметка осталась в 653 изображениях, 716 оказались без аннотаций.
3. **Прунинг** — 717 неразмеченных изображений (716 из raw_part2 + Alikino-2-8) перенесены в `data/energy_obj_unlabeled` для доразметки. Осталось 864 изображения, все с непустыми метками.

Все 1369 изображений raw_part2 учтены: 653 в датасете + 716 в пуле на доразметку, потерь нет.

## Структура каталогов

```text
data/energy_obj/
├── images/
│   ├── train/          # 619 JPEG-тайлов
│   ├── val/            # 123
│   └── test/           # 122
├── labels/
│   ├── train/          # по одному .txt на изображение (тот же stem)
│   ├── val/
│   └── test/
├── geo/
│   ├── train/          # .jgw (864) и .prj (524) файлы привязки
│   ├── val/
│   └── test/
├── classes.txt         # список классов (порядок = YOLO id)
├── metadata.json       # машиночитаемая сводка (источники, сплиты, классы, конфликты)
└── README.md           # автогенерируемое описание
```

Сплиты намеренно плоские: файл метки ищется по stem'у изображения (`images/train/X.jpg` ↔ `labels/train/X.txt`), как требует `YOLOTxtDataset`.

## Сплиты

Сплиты детерминированы (`--seed 42`). Изображения из исходной сборки сохранили свои сплиты; замерженные из raw_part2 распределены тем же сидом.

| Сплит | Изображений | Боксов |
|---|---:|---:|
| train | 619 | 3428 |
| val | 123 | 773 |
| test | 122 | 709 |
| **итого** | **864** | **4910** |

Изображения — JPEG, преимущественно 10000×10000 px; краевые тайлы региональных мозаик меньше (например 10000×5226, 4956×10000).

## Классы

Порядок в `classes.txt` задаёт YOLO id (id непрерывны, `class_id_map` не требуется):

| id | Имя | Аннотаций | Изображений с классом |
|---|---|---:|---:|
| 0 | `substation` | 7 | 4 |
| 1 | `supports 0,4` | 1041 | 129 |
| 2 | `supports 10` | 3603 | 691 |
| 3 | `supports 35` | 155 | 34 |
| 4 | `transformer` | 104 | 85 |

Распределение по сплитам (число боксов):

| id | Класс | train | val | test |
|---|---|---:|---:|---:|
| 0 | substation | 6 | 1 | 0 |
| 1 | supports 0,4 | 740 | 133 | 168 |
| 2 | supports 10 | 2494 | 593 | 516 |
| 3 | supports 35 | 116 | 30 | 9 |
| 4 | transformer | 72 | 16 | 16 |

Заметен сильный дисбаланс: `supports 10` доминирует (73% боксов), а `substation` представлен всего 7 аннотациями — при обучении стоит учитывать (веса классов, аугментации, пороги).

## Именование изображений

Шаблон: `<регион>-<столбец>-<строка>.jpg` — тайл сетки мозаики региона. Регионы датасета: Obvinsk, zukai, Силново-Терехино_24-25_03, kusher, Mendeleevo, Alikino, NPZ_OSKINO, Konusyata, savino, Mal_kazan, 35кВ_2, LISTVA, 35кВ_1, GAZ, KARPOVKA.

Имена должны быть уникальны во всём датасете (плоская выкладка) — скрипт сборки падает при коллизиях.

## Пространственная привязка (geo/)

К каждому тайлу в исходных экспортах шли файлы привязки, они скопированы в `geo/<split>/`:

- `.jgw` — world-файл (6 чисел: размер пикселя X, повороты, размер пикселя Y (отрицательный), координаты левого верхнего угла центра пикселя). 864 шт. — по одному на изображение.
- `.prj` — проекция в WKT. 524 шт. (не у всех тайлов): `MSK МСК-59 зона 1 Пермский край` (Крассовского, Transverse Mercator на основе EPSG-очевидных параметров). Координаты в метрах.

Geo-файлы не нужны для обучения, но позволяют привязать предсказания модели к карте и резать новые тайлы в тех же системах координат.

## Метаданные

`metadata.json` — машиночитаемая сводка: источники (`source_root`, `merge_source_roots`), счётчики (`total_images`, `splits`, `geo_files`), классы с числом аннотаций, список `unmatched_labels` (метки без изображения, не перенесены — 1 файл из energy2), `resolved_label_conflicts` (5 случаев дубликатов меток), `pruned_unlabeled` (указатель на пул доразметки).

## Пул на доразметку

`data/energy_obj_unlabeled/` — 717 изображений с пустыми метками и `manifest.json` (исходный сплит каждого изображения). Workflow: разметить в Label Studio → экспорт YOLO → мерж обратно. Подробности в [annotation.md](annotation.md).

## Пересборка и обновление

```bash
# план без записи файлов
uv run python scripts/prepare_energy_dataset.py --dry-run
# полная пересборка (управляемые файлы перезаписываются)
uv run python scripts/prepare_energy_dataset.py --force
# мерж нового экспорта Label Studio
uv run python scripts/prepare_energy_dataset.py --merge --source-root <export root> --dry-run
uv run python scripts/prepare_energy_dataset.py --merge --source-root <export root>
# вынести изображения без аннотаций в пул доразметки
uv run python scripts/prune_unlabeled.py --dry-run
uv run python scripts/prune_unlabeled.py
```

Скрипты перезаписывают `README.md`, `metadata.json`, `classes.txt` и содержимое `images|labels|geo/<split>`; не входящие в список управляемых файлы не трогают.
