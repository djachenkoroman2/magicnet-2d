Ты опытный Python/ML инженер, который аккуратно развивает существующий проект `magicnet-2d` для обучения и инференса моделей object detection на локальных геопривязанных изображениях энергетической инфраструктуры.

Контекст проекта:
- подготовленный датасет детекции лежит в `data/energy_obj/` (YOLO-формат: `images/<split>/`, `labels/<split>/`, `geo/<split>/`, `classes.txt`, `metadata.json`, `README.md`);
- изображения — большие ортотрансформированные тайлы ~10000×10000 px, целевые объекты мелкие (медианный бокс ~0.02% площади кадра, типично 50–165 px);
- обучение на целых кадрах с ресайзом в 608px не работает (mAP@0.5 ≈ 0.0004 после ~2850 эпох, см. `log/yolov3_d53_energy_obj_mmdet_e2800_to_e3200`), поэтому принято решение обучать на тайлах;
- принятые параметры тайлинга: размер тайла 1280×1280 px, шаг 1024 px (перекрытие 20%), доля пустых фоновых чипов 10–20% (обоснование — `doc/training_recommendations.md`, раздел «Как выбрать размер тайла»);
- пайплайн подготовки датасета: `scripts/prepare_energy_dataset.py` + `src/magicnet_2d/energy_dataset.py`, есть `tests/test_energy_dataset.py`;
- обучение: MMDetection через `scripts/train.py` и TOML-конфиги в `configs/project/` (датасет типа `YOLOTxtDataset`), также есть YOLO-пайплайн (`scripts/yolo_train.py`, `configs/yolo/*.yaml`).

Цель:
- создать ВАРИАНТ датасета с тайлингом, НЕ разрушая исходный;
- исходная разметка в `data/energy_obj/` должна остаться нетронутой (ни файлы, ни имена, ни сплиты);
- тайлинг — физический: чипы записываются на диск как обычные изображения + YOLO-метки, чтобы с ними работали существующие пайплайны без изменения кода обучения.

Что нужно сделать:
1. Изучи текущую структуру проекта, особенно:
   - `scripts/prepare_energy_dataset.py`;
   - `src/magicnet_2d/energy_dataset.py`;
   - `tests/test_energy_dataset.py`;
   - `data/energy_obj/README.md` и `data/energy_obj/metadata.json`;
   - `doc/training_recommendations.md`.
2. Реализуй логику тайлинга в `src/magicnet_2d/` (например, модуль `tiling.py`) и точку входа `scripts/tile_energy_dataset.py` в стиле существующих скриптов:
   - параметры: `--source-root` (по умолчанию `data/energy_obj`), `--output-root` (по умолчанию `data/energy_obj_tiles`), `--tile-size` (1280), `--stride` (1024), `--empty-frac` (0.15), `--seed`, `--force`, режим `--dry-run`;
   - чипы наследуют сплит родительского изображения: из `images/train` → в `images/train` тайлового датасета и т.д.;
   - имя чипа кодирует источник и положение, например `<stem>__x<i>_y<j>.jpg` — по имени должно быть однозначно восстановимы исходное изображение и координаты окна;
   - метки переводятся из нормализованных координат кадра в пиксельные координаты чипа, нормализуются обратно в [0,1] на размер чипа;
   - боксы обрезаются по границам чипа; боксы полностью вне чипа пропускаются; боксы, вырожденные после обрезки (сторона < 2 px), отбрасываются со статистикой;
   - пустые чипы (без боксов после обрезки) не пишутся все, а отбираются детерминированно (`--seed`) в доле `--empty-frac` от общего числа чипов соответствующего изображения (минимум — сохранять хотя бы один пустой чип на изображение, если он есть);
   - `classes.txt` копируется без изменений; class id не перекодируются.
3. Для тайлового датасета создай `metadata.json` и `README.md` по образцу `data/energy_obj/`:

   - явная ссылка на исходный датасет и на то, что `data/energy_obj/` не изменялся.
4. Geo-файлы (`.jgw`, `.prj`) в тайловый датасет НЕ копируй: обучающим чипам они не нужны, а привязка восстанавливается из имени чипа + сетки; это решение явно задокументируй в README тайлового датасета.
5. Подготовь конфиг для обучения на тайлах `configs/project/energy_obj_tiles_mmdet.toml`:

   - обрезка боксов по краям чипа и отбраковка вырожденных;

   - детерминированный отбор пустых чипов при заданном seed;
   - `--dry-run` не пишет файлы.

   - убедись, что `data/energy_obj/` побайтово не изменился (например, `git status`/контрольные суммы выборочно, по меткам и именам).
